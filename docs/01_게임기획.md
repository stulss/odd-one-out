## STEP 1 — 기술 선택

### 선택 결과

| 항목 | 내용 |
|---|---|
| **기술** | **Vanilla HTML + CSS + JavaScript (ES Modules)** — 게임 화면은 **DOM 그리드**, Canvas 2D는 **결과 카드 생성 전용** |
| **이유** | 이 게임의 화면은 "정지된 도형 격자 + 한 번의 입력"이다. 매 프레임 다시 그릴 것이 없다. 스크롤도 물리도 스프라이트 애니메이션도 카메라도 없다. **게임 루프가 필요 없는 게임에 게임 엔진을 쓰는 것은 순손실**이다. |
| **장점** | ① 라이브러리 0KB → 첫 로딩 3초 목표를 설계 단계에서 이미 달성 ② 히트 판정을 브라우저가 공짜로 처리 (좌표 계산·DPR 보정 코드 불필요) ③ CSS `transform`/`opacity`는 GPU 합성 → 60FPS 자동 ④ 차이를 CSS 값 한 줄로 정밀 표현 (`rotate: 3deg`) ⑤ 키보드 포커스·접근성 기본 제공 (과제의 키보드 조작 요건 충족) ⑥ 빌드 도구 없이 저장 → 새로고침 = 즉시 확인 |
| **단점** | ① 셀 200개 이상이면 DOM 비용 발생 → **최대 48셀 상한 설계** ② 대량 파티클에 불리 → CSS 애니메이션 3종으로 제한 ③ 프레임 단위 정밀 연출 불가 → 이 게임엔 불필요 |
| **대체 기술** | **1순위 Canvas 2D 단독** (셀 100개 초과 요구 시 `render.js`만 교체 — 아키텍처가 렌더러를 분리해 둠) · **2순위 PixiJS** (WebGL 파티클이 정말 필요해질 때) · **비채택 Phaser / Unity WebGL / Godot / Three.js / Unreal** |

### 유명 엔진을 쓰지 않은 근거 (수치)

| 후보 | 최소 전송 크기 (gzip) | 첫 플레이까지 | 판정 |
|---|---|---|---|
| Vanilla + DOM | **~25KB** | **~0.8초** | ✅ 채택 |
| Canvas 2D 단독 | ~28KB | ~0.9초 | 예비안 |
| PixiJS | ~140KB | ~1.8초 | 과함 |
| Phaser 3 | ~450KB | ~3.0초 | 목표 위반 |
| Three.js | ~180KB + 에셋 | ~2.5초 | 불필요 |
| Godot Web | ~8MB (wasm) | ~8초 | 목표 위반 |
| Unity WebGL | ~15MB+ | ~15초 | 치명적 (iOS 메모리 이슈) |

> **판단 기준:** 이 게임이 60FPS로 갱신해야 하는 픽셀 수는 거의 0이다. 엔진의 강점(렌더 루프·씬 그래프·물리)은 전부 유휴 자원이 되고, 엔진의 비용(번들 크기·초기화 시간)은 **첫 로딩 3초라는 최우선 지표를 직접 파괴**한다.

## STEP 2 — 그래픽 스타일

### 선택: **Geometric Flat (CSS/SVG 도형)** — 보조 **Minimal Cartoon**

- **MVP 이미지 파일 개수 0개.** 모든 게임 오브젝트는 CSS `border-radius` / `clip-path` / 인라인 SVG로 생성.
- **왜 픽셀·AI 생성 2D가 아닌가:** 이 게임의 재미는 **미묘한 차이**다. 차이를 1px·3°·5% 단위로 **정확히 제어**해야 난이도 곡선이 성립한다. 래스터 이미지는 축소·DPR 보정에서 차이가 뭉개지거나(너무 쉬움) 앤티에일리어싱 노이즈가 생긴다(불공정한 실패). 벡터/CSS만이 차이를 **수치로 보증**한다.
- **컬러 시스템 (다크 기본 — 눈 피로 ↓, 도형 대비 ↑)**

```css
:root{
  --bg:#0E1116; --bg-soft:#161B22; --line:#232A34;
  --ink:#E8EDF4; --ink-dim:#8A94A6;
  --brand:#5EE6C5;   /* 성공 */
  --warn:#FFB454;    /* 시간 경고 */
  --bad:#FF6B6B;     /* 실패 */
  --cell:#3D6BFF;    /* 기본 오브젝트 */
}
```

- **폰트:** 시스템 폰트만 (웹폰트 0KB) — `-apple-system, "Apple SD Gothic Neo", Pretendard, "Malgun Gothic", sans-serif`
- **모션 원칙:** 애니메이션 **3종만** — ① 정답 팝(scale 1→1.18→1) ② 오답 흔들림(translateX ±6px) ③ 스테이지 전환(opacity + translateY 12px). 전부 200ms 이하. `prefers-reduced-motion` 및 **화면 내 "움직임 줄이기" 토글** 존중.

```
[게임 밖 브랜딩]
AI 이미지 생성(무료 티어)
  → 육안 검수 (기존 IP 유사성 확인)

  → /assets 배치 (총합 80KB 이하)
```

## STEP 6 — 3D 에셋 (Meshy)

### 결론: **MVP에서 3D를 사용하지 않는다.**

- GLB 최소 실사용 크기(Draco + KTX2) ≈ 300KB~1MB → **전체 예산(100KB)의 3~10배**
- 3D 렌더에 Three.js(~180KB) 추가 필요 → 로딩 3초 목표 붕괴
- 이 게임의 재미(미묘한 2D 차이 인식)에 3D 기여도가 없다. 오히려 원근·조명이 차이를 왜곡해 **불공정한 실패**를 만든다.

### v1.2 이후 굿즈/프로필 용도로만 조건부 사용 (게임 내 미사용)

| 대상 | Meshy 프롬프트 | Polygon | Texture | Material | Animation | Format | Compression |
|---|---|---|---|---|---|---|---|
| 마스코트 | `Cute minimal geometric mascot made of a rounded cube body and two sphere eyes of slightly different size, matte slate blue with mint green accent, flat toy-like proportions, original design, no branding` | ≤3,000 tri | 512² baseColor 1장 | Unlit/Toon 1개 | Idle 2초 루프 1개 | GLB | Draco + KTX2(ETC1S) |
| 오브젝트 | `Simple rounded cube game token, matte finish, single flat color, no texture detail, low poly, original` | ≤500 tri | 없음(버텍스 컬러) | Unlit 1개 | 없음 | GLB | Draco |
| 장식물 | `Minimal floating geometric shard, low poly, matte single color, original design` | ≤300 tri | 없음 | Unlit | 없음 | GLB | Draco |
| 배경 오브젝트 | `Very low poly abstract grid platform, flat matte surface, no props, original` | ≤800 tri | 없음 | Unlit | 없음 | GLB | Draco |

**필수 후처리:** `Meshy → GLB → Blender Decimate → 텍스처 512 이하 → 머티리얼 1개 병합 → gltf-transform(Draco+KTX2) → **최종적으로 스프라이트 시트로 렌더해 2D로 반입**`
즉 3D는 **에셋 제작 도구**로만 쓰고 런타임에는 언제나 2D로 들어온다.

## STEP 7 — UI 설계

### 대응 해상도 (모바일 + PC 병행)

| 기준 | 논리 해상도 | 대응 |
|---|---|---|

| **모바일 표준** | **390×844** | **모바일 설계 기준** |
| 모바일 대형 | 412×915 | 여백 확대 |
| **PC 기준 A** | **1366×768** | **과제 기준 해상도 1** — 게임판 최대 폭 560px 중앙 고정 |
| **PC 기준 B** | **1920×1080** | **과제 기준 해상도 2** — 좌우 여백만 증가, 게임판 크기 동일 |

**레이아웃 규칙**
- `100dvh` 사용(iOS 주소창 대응), `env(safe-area-inset-*)` 패딩.
- 세로 3분할: **헤더 12% / 플레이 영역 76% / 하단 12%**
- **게임판은 `min(92vw, 92vh - 220px, 560px)` 정사각형** → 어떤 해상도에서도 잘리지 않고 가로 스크롤이 생기지 않는다.
- 최소 조작 타깃 **44×44px 보장** → 셀 크기가 44px 미만이 되면 **열/행 수를 강제로 줄인다.** 난이도는 "차이의 미묘함"으로만 올린다.
- **가로 넘침 금지:** `html,body{overflow-x:hidden}` + 모든 컨테이너 `max-width:100%`.

- **START → GAME 사이에 로딩 화면 없음.** 첫 입력 즉시 1스테이지 렌더.

## STEP 10 — 랜덤(시드) 시스템

**요구:** 같은 URL → 어느 기기에서든 **완전히 동일한 문제**. `Math.random()` 금지.

```js
// xmur3: 문자열 → 32bit 시드
function xmur3(str){
  let h = 1779033703 ^ str.length;
  for (let i = 0; i < str.length; i++){
    h = Math.imul(h ^ str.charCodeAt(i), 3432918353);
    h = (h << 13) | (h >>> 19);
  }
  return () => {
    h = Math.imul(h ^ (h >>> 16), 2246822507);
    h = Math.imul(h ^ (h >>> 13), 3266489909);
    return (h ^= h >>> 16) >>> 0;
  };
}

// mulberry32: 32bit 시드 → [0,1)
function mulberry32(a){
  return () => {
    a |= 0; a = (a + 0x6D2B79F5) | 0;
    let t = Math.imul(a ^ (a >>> 15), 1 | a);
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}

// 스테이지별 독립 스트림 — 같은 스테이지를 다시 뽑아도 결과 동일
const stageRng = (rootKey, n) => mulberry32(xmur3(`${rootKey}#${n}`)());
```

```js
const AB = '23456789ABCDEFGHJKLMNPQRSTUVWXYZ';           // 32자
const encode = s => { let o=''; for(let i=0;i<6;i++){ o = AB[s & 31] + o; s >>>= 5; } return o; };
```

**손상 복구 (과제 카드 4 핵심)**

```js
function load(){
  try{
    const raw = localStorage.getItem(KEY);
    if (!raw) return structuredClone(DEFAULT);          // 빈 값
    const parsed = JSON.parse(raw);                      // 글자만 있는 값 → 여기서 throw
    if (typeof parsed !== 'object' || parsed === null) return structuredClone(DEFAULT);
    return coerce(parsed);                               // 필수 항목 누락 → 기본값으로 채움
  } catch(e){
    return structuredClone(DEFAULT);                     // 손상 → 조용히 기본값
  }
}
// coerce: DEFAULT를 순회하며 타입이 맞는 값만 채택, 나머지는 기본값
function coerce(o, def = DEFAULT){
  const out = structuredClone(def);
  for (const k in def){
    if (!(k in o)) continue;
    if (typeof def[k] === 'object' && def[k] !== null && !Array.isArray(def[k]))
      out[k] = coerce(o[k] ?? {}, def[k]);
    else if (typeof o[k] === typeof def[k]) out[k] = o[k];
  }
  return out;
}
```

**규칙**
- **개인정보·식별자 저장 금지.** 이름/이메일/UUID/IP/기기정보 저장하지 않는다. 저장되는 것은 점수·설정·날짜 문자열뿐.
- 시크릿 모드/용량 초과 대비: 모든 접근을 `try/catch`로 감싸고 실패 시 **메모리 객체로 폴백**해 게임은 정상 동작.
- 연속 출석: `lastPlayDate`가 어제면 `count+1`, 오늘이면 유지, 그 외면 `1`로 리셋.
- 설정에 **"기록 초기화"** 버튼 필수.

## STEP 18 — 핵심 알고리즘

### 1) 스테이지 생성

```js
const MAX_CELLS = 48;
const MIN_TOUCH = 44;              // px
let   TUNE_T    = 4.4;             // ★ 난이도 상수 (과제 카드 3에서 조정하는 유일한 값)

function makeStage(rootKey, n, boardPx, prevAnswer){
  const rnd  = stageRng(rootKey, n);
  const t    = Math.min(n / 40, 1);
  const ease = t * t * (3 - 2 * t);            // smoothstep: 초반 완만, 후반 급격

  // ── 그리드 (세로가 길므로 rows ≥ cols)
  let cols = clamp(2 + Math.floor(n / 4), 2, 6);
  let rows = clamp(3 + Math.floor(n / 3), 3, 8);
  while (boardPx / Math.max(cols, rows) < MIN_TOUCH && (cols > 2 || rows > 3)){
    if (cols / rows > 0.7) cols--; else rows--;   // 44px 보장이 난이도보다 우선
  }
  if (cols * rows > MAX_CELLS) rows = Math.floor(MAX_CELLS / cols);

  // ── 차이 축: 스테이지가 오를수록 어려운 축의 가중치 상승
  const axis  = pickWeighted(AXIS_POOL, ease, rnd);
  const spec  = DIFF_AXES[axis];
  const delta = lerp(spec.easy, spec.hard, ease) * (0.85 + rnd() * 0.3);  // ±15% 흔들기

  // ── 제한 시간: TUNE_T가 클수록 어려워진다 (6.0초 → 1.6초)
  const timeLimit = Math.max(1.6, 6.0 - ease * TUNE_T) + (cols * rows > 24 ? 0.6 : 0);

  // ── 정답 위치: 직전과 같은 칸 금지
  let answer;
  do { answer = Math.floor(rnd() * cols * rows); } while (answer === prevAnswer);

  return { n, cols, rows, answer, axis, delta, timeLimit,
           shape: SHAPES[Math.floor(rnd() * SHAPES.length)],
           baseHue: Math.floor(rnd() * 360) };
}
```

```js
let deadline = 0, paused = false, remain = 0, rafId = null;

function start(sec){ deadline = performance.now() + sec * 1000; if (!rafId) loop(); }
function pause(){ if (paused) return; paused = true; remain = deadline - performance.now(); }
function resume(){ if (!paused) return; paused = false; deadline = performance.now() + remain; }

function loop(){                       // ★ rAF 루프는 앱 전체에서 이 하나뿐
  rafId = requestAnimationFrame(loop);
  if (paused || state !== 'PLAY') return;
  const left = (deadline - performance.now()) / 1000;
  gauge.style.transform = `scaleX(${Math.max(0, left / stage.timeLimit)})`;
  if (left <= 0) gameOver('timeout');
}

document.addEventListener('visibilitychange', () => document.hidden ? pause() : resume());
window.addEventListener('blur',  pause);
window.addEventListener('focus', resume);
```

## 지금 당장 시작해야 할 **첫 번째 작업** (단 하나)

> ### 「`index.html` 한 파일에, 4×6 회색 사각형 격자 중 하나만 살짝 회전시켜 놓고, 그걸 누르면 다음 격자가 나오는 것까지 만들어서 **오늘 안에 본인 기기 브라우저로 열어본다.**」

**왜 이것 하나인가**

1. **이 게임이 재미있는지는 이 100줄로 전부 판명된다.** 격자를 보고 다른 하나를 찾는 그 1초의 감각이 재미없다면 세계관도 캐릭터도 결과 카드도 전부 무의미하다. 가장 싼 비용으로 가장 큰 불확실성을 제거하는 작업이 이것뿐이다.
2. **"직접 열어본다"까지가 작업 범위인 이유** — 코드가 돌아가는 것과 손가락으로 누르는 감각은 다른 문제다. 셀 크기감, 반응 속도, 차이의 인지 난이도는 실제 화면에서만 알 수 있고, **난이도 곡선 전체가 그 감각 위에 세워진다.**
3. **파일 1개인 이유** — 폴더 구조, 모듈 분리, 컬러 시스템, 상태 머신은 나중에 해도 늦지 않다. 1인 개발이 실패하는 가장 흔한 방식은 **재미를 확인하기 전에 구조를 먼저 짓는 것**이다.

**Day 1 완료 기준**
- [ ] 격자가 화면에 꽉 차게 보인다
- [ ] 다른 하나를 눈으로 찾을 수 있다
- [ ] 그것을 정확히 누를 수 있다
- [ ] 누르면 다음 격자가 나온다
- [ ] **10번 연속으로 하고 싶어진다** ← 이 항목이 실패하면 기획을 고친다, 코드를 늘리지 않는다
