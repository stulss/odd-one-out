# 과제 요구사항 ↔ 설계 매핑표

> 과제: **「내가 설계한 미니게임」** · 게임: **「딱 하나 이상함」**
> 이 문서는 **채점 기준이 설계 어디에서 충족되는지**를 1:1로 대응시킨 문서다.
> 상세 설계는 `01_게임기획.md`, 진행 상황은 `../작업내역_체크리스트.md`.

## 0. 한 문장 정의 (카드 1 · 첫 번째 행동)

> **플레이어는 `화면의 격자 칸`을 조작해 `여럿 중 딱 하나 다른 칸을 찾아 선택`하면 성공하고,
> `제한 시간이 0이 되면` 실패한다.**

- **핵심 조작 1개:** 선택 (마우스 클릭 / 터치 = 같은 동작. 키보드 방향키+Enter는 동등한 대체 경로)
- **표현 수단:** 도형과 글자만 — 이미지 파일 0개
- **한 판 길이:** 30초 ~ 3분 (스테이지당 1.6~6.0초)

## 1. 완료기준 4항목

| 과제 완료기준 | 충족 방식 | 근거 위치 |
|---|---|---|
| 공개 주소에서 **게임 규칙·조작 방법·현재 상태**가 보인다 | GAME 화면 하단에 3줄 상시 노출 — `규칙: 다른 하나를 찾아 선택` / `조작: 클릭·탭 · 방향키+Enter · P=일시정지` / `상태: 진행 중 · STAGE 07 · 난이도 T=4.4`. START 화면에도 규칙 블록 별도 표시 | 기획서 STEP 7 화면 정의 |
| **조작 1회에 화면 상태가 바뀌고 성공/실패가 구분된다** | 정답 → 팝 애니메이션 + 점수 증가 + 다음 스테이지. 오답 → 흔들림 + 시간 −1초. 시간 0 → RESULT 화면에 `실패 — 시간 초과` 명시 + 정답 위치 공개 | STEP 8 이벤트 흐름 |
| **다시 시작하면 현재 판이 초기화된다** | 현재 판 상태(점수·스테이지·타이머·콤보)는 **localStorage에 저장하지 않음** → 새 게임 시 자동으로 0. 최고 기록만 별도 키에 보존 | STEP 11 저장 스키마 |
| **음소거 또는 움직임 줄이기가 화면에서 작동한다** | 설정 시트에 `소리 [ON/OFF]`, `움직임 줄이기 [ON/OFF]` 두 개 모두 제공. 즉시 반영되고 설정은 보존 | STEP 8 AudioManager / STEP 2 모션 원칙 |

### 📌 카드 3 — 플레이 데이터로 난이도 조정
- **바꾸는 값: `TUNE_T` 단 하나** (제한 시간 감소 계수). 기본 4.4 → 후보 3.6 또는 5.2.
  `timeLimit = max(1.6, 6.0 − ease × TUNE_T)`
- **측정값 2개:** ① 도달 스테이지 수 ② 생존 시간(ms)
- **실패 원인 분류 3종:** `timeout`(시간 초과) / `wrong_streak`(오답 누적으로 시간 소진) / `quit`(중도 이탈)
- **현재 난이도 값이 화면에 보임:** 설정 시트와 GAME 하단 상태줄에 `난이도 T=4.4` 표시 ← 통과 기준
- **기록 도구:** `src/logger.js`가 매 판 종료 시 1행 추가, 10회 후 CSV 복사 버튼 활성화

### 📄 검증 안내서 초안 (참고용 — 실제 제출은 `../검증안내서.md`)

```
■ 어디로 가나요
https://odd-one-out-nine.vercel.app/

■ 무엇을 하나요  (3단계 · 30초)
1) 화면 가운데 [시작하기]를 누른다.
2) 격자에서 다른 하나를 찾아 클릭한다. (키보드는 방향키 + Enter)
3) 시간이 0이 되어 결과 화면이 나오면 [다시 하기]를 누른다.

■ 무엇이 보이면 통과인가요
- 화면 아래에 규칙 / 조작 / 현재 상태 세 줄이 계속 보인다.
- 다른 하나를 누르면 즉시 다음 격자로 넘어가고 STAGE 숫자가 올라간다.
- 엉뚱한 칸을 누르면 칸이 흔들리고 남은 시간이 줄어든다.
- 결과 화면에 '실패 — 시간 초과'와 도달 단계가 나온다.
- [다시 하기]를 누르면 STAGE가 1로, 점수가 0으로 돌아간다.
- 설정에서 [소리]를 끄면 즉시 무음, [움직임 줄이기]를 켜면 흔들림이 사라진다.

■ 안 될 때
- 화면이 비어 있으면 새로고침 (Ctrl+F5).
- 소리가 안 나면 화면을 한 번 클릭한 뒤 다시 시도 (브라우저 자동재생 정책).
- 기록이 이상하면 설정 → [기록 초기화].
```

보인다. 그런데 D-19/D-20에서 게임 내부 지표(지각 여유 %)로 다시 재보면 20~25단계 구간에서
**18~25%p** 차이가 난다 — 이 표의 반응 모델(`sim_difficulty.py`)이 고정된 탐색시간 공식을
쓰기 때문에, 실제로는 커진 난이도 차이가 단계 수 차이로 잘 안 옮겨진 것이다. 즉 **이 표는
"손잡이가 죽어있지 않다"는 확인용으로는 충분하지만, 정확한 최종값을 미세 조정하는 근거로는
약하다.** 최종값은 **T=4.4(기존값)를 유지**하기로 한다 — 원래 튜닝된 기준값이고, 자동 플레이
데이터가 이를 뒤집을 만큼 강한 신호를 주지 않기 때문이다. 사람이 실제로 플레이해 보고
체감상 너무 쉽다고 느끼면 5.4 쪽으로 옮기는 것을 권장한다.
