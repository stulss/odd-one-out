# 과제 요구사항 ↔ 설계 매핑표

> 과제: **「내가 설계한 미니게임」** · 게임: **「딱 하나 이상함」**
> 이 문서는 **채점 기준이 설계 어디에서 충족되는지**를 1:1로 대응시킨 문서다.
> 상세 설계는 `01_게임기획.md`, 진행 상황은 `../작업내역_체크리스트.md`.

---

## 0. 한 문장 정의 (카드 1 · 첫 번째 행동)

> **플레이어는 `화면의 격자 칸`을 조작해 `여럿 중 딱 하나 다른 칸을 찾아 선택`하면 성공하고,
> `제한 시간이 0이 되면` 실패한다.**

- **핵심 조작 1개:** 선택 (마우스 클릭 / 터치 = 같은 동작. 키보드 방향키+Enter는 동등한 대체 경로)
- **표현 수단:** 도형과 글자만 — 이미지 파일 0개
- **한 판 길이:** 30초 ~ 3분 (스테이지당 1.6~6.0초)

## 1. 완료기준 4항목

| 과제 완료기준 | 충족 방식 | 근거 위치 |
|---|---|---|
| 공개 주소에서 **게임 규칙·조작 방법·현재 상태**가 보인다 | GAME 화면 하단에 3줄 상시 노출 — `규칙: 다른 하나를 찾아 선택` / `조작: 클릭·탭 · 방향키+Enter · P=일시정지` / `상태: 진행 중 · STAGE 07 · 난이도 T=4.4`. START 화면에도 규칙 블록 별도 표시 | 기획서 STEP 7 화면 정의 |
| **조작 1회에 화면 상태가 바뀌고 성공/실패가 구분된다** | 정답 → 팝 애니메이션 + 점수 증가 + 다음 스테이지. 오답 → 흔들림 + 시간 −1초. 시간 0 → RESULT 화면에 `실패 — 시간 초과` 명시 + 정답 위치 공개 | STEP 8 이벤트 흐름 |
| **다시 시작하면 현재 판이 초기화된다** | 현재 판 상태(점수·스테이지·타이머·콤보)는 **localStorage에 저장하지 않음** → 새 게임 시 자동으로 0. 최고 기록만 별도 키에 보존 | STEP 11 저장 스키마 |
| **음소거 또는 움직임 줄이기가 화면에서 작동한다** | 설정 시트에 `소리 [ON/OFF]`, `움직임 줄이기 [ON/OFF]` 두 개 모두 제공. 즉시 반영되고 설정은 보존 | STEP 8 AudioManager / STEP 2 모션 원칙 |

## 2. 카드별 대응

### 📌 카드 1 — 30초 안에 이해되는 핵심 규칙
| 통과 기준 | 대응 |
|---|---|
| 공개 화면에서 시작 가능 | Cloudflare Pages 공개 URL, 로딩 화면 없이 첫 입력 즉시 플레이 |
| 상태가 성공·실패·진행 중 하나로 구분 | 상태 머신 `PLAY / STAGE_CLEAR / GAMEOVER`가 화면 텍스트와 1:1 대응 |
| 다시 시작 시 초기화 | `newGame()`이 런타임 상태 객체를 새로 만들고 저장값은 건드리지 않음 |

### 📌 카드 2 — PC 숨은 검사
| 검사 범주 | 설계상 대응 | QA# |
|---|---|---|
| 빠른 연속 입력 | `locked` 플래그 120ms — 조작 1회 = 결과 1회 보장 | 27 |
| 1366 ↔ 1920 창 크기 변경 | 게임판 `min(92vw, 92vh-220px, 560px)` 정사각형 + `overflow-x:hidden` | 29 |
| 포커스 이탈·복귀 | `blur/focus` + `visibilitychange` → 타이머 자동 일시정지·복귀 | 30 |
| 일시정지·재개 | `P` / `Esc` / ⏸ 버튼 → 남은 시간 `remain`에 정확히 보존 | 31 |
| 10분 실행 | **rAF 루프 앱 전체에 1개만**, DOM 노드 재사용(생성/삭제 0), 리스너 누적 없음 | 32 |

### 📌 카드 3 — 플레이 데이터로 난이도 조정
- **바꾸는 값: `TUNE_T` 단 하나** (제한 시간 감소 계수). 기본 4.4 → 후보 3.6 또는 5.2.
  `timeLimit = max(1.6, 6.0 − ease × TUNE_T)`
- **측정값 2개:** ① 도달 스테이지 수 ② 생존 시간(ms)
- **실패 원인 분류 3종:** `timeout`(시간 초과) / `wrong_streak`(오답 누적으로 시간 소진) / `quit`(중도 이탈)
- **현재 난이도 값이 화면에 보임:** 설정 시트와 GAME 하단 상태줄에 `난이도 T=4.4` 표시 ← 통과 기준
- **기록 도구:** `src/logger.js`가 매 판 종료 시 1행 추가, 10회 후 CSV 복사 버튼 활성화

### 📌 카드 4 — 저장과 복구
| 구분 | 항목 |
|---|---|
| **새 판에서 초기화** | 현재 점수 · 현재 스테이지 · 타이머 · 콤보 · 실패 원인 |
| **다시 접속해도 보존** | 최고 단계 · 최고 점수 · 최고 반응속도 · 오늘의 문제 기록 · 연속 출석 · 설정 |
| **저장값 없을 때 기본값** | `DEFAULT` 객체 (STEP 11) |
| **4가지 저장 상태 검사** | ① 정상값 ② 빈 값 `""` ③ 글자만 `"abc"` ④ 필수 항목 누락 `{"v":1}` → 전부 기본값으로 정상 실행, 콘솔 오류 0 |

### 📌 카드 5 — 손맛과 선택권
| 항목 | 결정 |
|---|---|
| 효과를 붙일 사건 | **성공(정답 선택)** 1개 |
| 효과 종류 | ① 효과음(WebAudio 짧은 상승음) ② 시각 효과(셀 팝 + 민트 링 확산) |
| 줄이기·끄기 선택 | `소리 OFF` → 즉시 무음 / `움직임 줄이기 ON` → 팝·흔들림·링 제거, **색 점멸로만 대체**(사건 인지 자체는 유지) |
| 즉시 반영 | 토글 클릭 시 다음 프레임부터 적용, 재시작 불필요 |

## 4. 제출물 템플릿

### 📄 검증 안내서 (배포 후 값만 채우기)

```
■ 어디로 가나요
https://oddone.pages.dev

■ 무엇을 하나요  (3단계 · 30초)
1) 화면 가운데 [시작하기]를 누른다.
2) 격자에서 다른 하나를 찾아 클릭한다. (키보드는 방향키 + Enter)
3) 시간이 0이 되어 결과 화면이 나오면 [다시 하기]를 누른다.

■ 무엇이 보이면 통과인가요
- 화면 아래에 규칙 / 조작 / 현재 상태 세 줄이 계속 보인다.
- 다른 하나를 누르면 즉시 다음 격자로 넘어가고 STAGE 숫자가 올라간다.
- 엉뚱한 칸을 누르면 칸이 흔들리고 남은 시간이 줄어든다.
- 결과 화면에 '실패 — 시간 초과'와 도달 단계가 나온다.
- [다시 하기]를 누르면 STAGE가 1로, 점수가 0으로 돌아간다.
- 설정에서 [소리]를 끄면 즉시 무음, [움직임 줄이기]를 켜면 흔들림이 사라진다.

■ 안 될 때
- 화면이 비어 있으면 새로고침 (Ctrl+F5).
- 소리가 안 나면 화면을 한 번 클릭한 뒤 다시 시도 (브라우저 자동재생 정책).
- 기록이 이상하면 설정 → [기록 초기화].
```

## 5. 기획서와의 차이 (과제 때문에 추가된 것)

| 추가 항목 | 원래 기획에 없던 이유 | 지금의 처리 |
|---|---|---|
| PC 해상도 1366/1920 | 모바일 세로 전용 기획이었음 | 게임판 폭 상한 560px 고정 + 좌우 여백 확장으로 대응 |
| 일시정지·재개 | 30초 게임에 불필요하다고 판단했음 | `P`/`Esc`/버튼 추가, 타이머 `remain` 보존 |
| 10분 연속 실행 | 세션 3분 가정 | rAF 루프 1개 원칙 + 노드 재사용으로 누수 차단 |
| 규칙·조작 상시 표시 | 튜토리얼 1회로 대체하려 했음 | GAME 하단 3줄 고정 (튜토리얼은 유지하되 보조로 격하) |
| 난이도 값 화면 노출 | 내부 상수였음 | 설정과 상태줄에 `T=4.4` 표시 |
| 플레이 로거 | MVP 제외 대상이었음 | `logger.js` 추가 — **단, 개인정보 미수집·로컬 전용** |
