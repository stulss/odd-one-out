## GitHub Pages를 고른 이유 (4가지)

**1. 계정을 하나도 새로 만들지 않아도 됩니다.**
바탕화면에 GitHub Desktop이 이미 설치되어 있습니다. Cloudflare를 쓰려면 계정 생성 → 이메일 인증 → 저장소 연결이라는 단계가 추가되는데, 이 프로젝트에서 가장 비싼 자원은 서버 비용이 아니라 **남은 시간**입니다.

**2. 100GB/월 제한이 이 프로젝트에서 문제가 되지 않습니다.**
이 게임의 전체 전송 크기는 약 60KB입니다. 100GB ÷ 60KB ≈ **약 170만 회 방문**입니다. 과제로 제출하는 웹 미니게임이 월 170만 방문을 넘길 확률은 사실상 0이고, 만에 하나 그런 일이 벌어진다면 그건 문제가 아니라 축하할 일이며, 그때 옮기면 됩니다.

**3. 나중에 옮기는 비용이 거의 0입니다.**
정적 파일뿐이라 Cloudflare Pages에서 **같은 GitHub 저장소를 그대로 연결**하면 5분 안에 이전됩니다. 코드 수정도 필요 없습니다. 즉 지금 GitHub Pages를 고르는 것은 되돌릴 수 없는 선택이 아닙니다. 되돌리기 싼 선택을 먼저 하는 게 맞습니다.

**4. 저장소 자체가 작업 근거가 됩니다.**
커밋 히스토리가 남으므로 "언제 무엇을 만들었는지"가 자동으로 증명됩니다. 과제 제출 맥락에서 이건 부수적이지만 실질적인 이점입니다.

- 실제로 트래픽이 몰리기 시작할 때 (국내 응답 속도 차이가 체감됨)

→ **셋 중 하나라도 해당되면 그때 옮깁니다.** 지금은 아닙니다.

## 배포 절차

### 1. 저장소 만들기

GitHub Desktop → `File → Add local repository` → `C:\Users\stuls\Desktop\developer stuls\odd-one-out` 선택
→ `Publish repository` → 이름 `odd-one-out`, **Public**으로 공개 (Private이면 Pages가 안 됩니다)

명령줄로 하려면:

```bash
cd "C:/Users/stuls/Desktop/developer stuls/odd-one-out" && git init && git add -A && git commit -m "딱 하나 이상함 MVP"
```

### 2. Pages 켜기

저장소 → **Settings → Pages** → Source: `Deploy from a branch` → Branch: `main` / 폴더: `/ (root)` → Save
1~3분 뒤 아래 주소가 열립니다.

```
https://<사용자명>.github.io/odd-one-out/
```

### 3. 반드시 확인할 것

- [ ] **저장소가 Public인가** — Private이면 Pages가 동작하지 않습니다
- [ ] `.nojekyll` 파일이 루트에 있는가 — 없으면 Jekyll이 일부 파일을 걸러낼 수 있습니다 (이미 추가해 뒀습니다)
- [ ] 주소 끝의 **슬래시** — `.../odd-one-out/` (슬래시 없으면 상대 경로가 어긋날 수 있습니다)
- [ ] 게임이 하위 경로(`/odd-one-out/`)에서 정상 동작하는가
      → 코드가 절대 경로를 쓰지 않고 `./src/main.js` 같은 상대 경로만 쓰도록 이미 맞춰 뒀습니다
- [ ] 공유 링크가 하위 경로를 유지하는가
      → `shareUrl()`이 `location.origin + location.pathname`을 쓰므로 자동으로 맞습니다

### 4. 이후 업데이트

GitHub Desktop에서 커밋 → Push 하면 1~3분 뒤 자동 반영됩니다. 별도 빌드나 배포 명령이 없습니다.
